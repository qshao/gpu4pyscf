# Disk-backed DF and CPU–GPU transfers

**Goal:** Support single-GPU molecular DF without retaining the full CDERI tensor
in host or GPU RAM, preserving precision and scientific settings.

**Architecture:** Opt-in `DF.cderi_storage = 'disk'`. A temporary row-major FP64
file receives transformed AO-pair blocks during construction. Bounded pinned
host buffers stage writes and double-buffered reads; device events protect
buffer reuse and overlap H2D with the consumer's computation. GPU-resident
storage remains the default. Disk mode increases transfer volume compared
with resident data; do not claim otherwise. Native metric/factor storage and
OS file cache remain outside the staging budget.

**Files:** new `gpu4pyscf/df/disk.py`; integrate `df.py`; regression tests under
`benchmarks/single_gpu/test_disk_df.py`; evidence under the same benchmark
directory. Preserve all preceding campaigns and unknown `record` file.

The optional `cderi_cache_bytes` setting reserves a separately bounded GPU
prefix, filled on GPU during construction. Prefix rows avoid repeated disk
reads and H2D for complete contraction blocks. Default zero retains minimum
GPU storage. This cache remains experimental: the repeated small-case timing
campaign rejected it as a performance improvement (29 versus18iterations).
The default staging budget is128MiB; the existing evaluator's indivisible
AO-pair groups can require more. Tamoxifen needs995,840,640B explicit build
workspace, so the larger qualification uses a configured1GiB staging budget.
The exact minimum-group assertion now raises an informative MemoryError;
other evaluator allocation failures retain their original chained cause.
